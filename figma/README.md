## Manifest and provenance

The [asset manifest](../metadata/assets.json) records each file's path and SHA-256, with origin and rights information. It also covers assets outside this directory; select entries whose `path` begins with `figma/`.

For this collection, upstream origin and redistribution rights remain **unverified**. Source URLs, kit versions, platform, appearance, and synchronization dates are not established. A matching hash identifies the bytes reviewed; it does not establish authorship, licensing, or agreement with a current Apple design resource.

Do not describe these images as known licensed Apple exports, current OS 27 assets, or a synchronized official Figma kit. Appearance labels such as “Clear” are filenames, not evidence of a system setting or a supported SDK feature.

## Before reusing or changing an asset

1. Locate the exact upstream resource and applicable license. [Apple Design Resources](https://developer.apple.com/design/resources/) is the official starting point for Apple's current design tools and templates, but a link to that page is not provenance for these existing files.
2. Establish the specific source, version or publication date, intended platform and appearance, and permitted uses. Check redistribution rights separately from permission to use a resource when designing an app.
3. Record that evidence and any attribution obligations through the repository's asset-manifest maintenance process before representing a file as verified.
4. Review any replacement for visual and accessibility changes. Preserve meaningful distinctions between functional controls, content, and platform-specific materials.

Do not delete, recolor, regenerate, or replace the existing art merely to make it appear current. Without established source and rights, retain the files as an unverified reference collection rather than claiming a design-resource update.
